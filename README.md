# BEAT LAB v6.0 — 모바일 웹앱 + 클라우드 오디오 분석

## 무엇이 작동하나요?
- 스마트폰 브라우저에서 드릴/트랩/붐뱁 비트 만들기, 16스텝 드럼, 808, 멜로디 피아노 롤, 코드 패드, BPM 조절, 재생/정지, 기기 로컬 저장
- 마이크 녹음 또는 음악 파일 업로드 → 클라우드 Python/Librosa 서버에서 BPM, 조성, 에너지, 밝기, 킥 후보, 피치 클래스 추정 → 그 특징을 반영한 새 비트 생성
- 서버로 보낸 파일은 분석 후 임시 파일 삭제. 오디오는 최대 30MB, 처음 90초만 분석.
- 링크 입력은 원본 페이지를 열기만 합니다. YouTube/Spotify 오디오를 자동으로 추출하지 않습니다.
- AI는 실제 오디오 신호 분석 + 규칙/확률 기반 비트 생성입니다. 신경망 음악 생성이나 정밀 악기 분리는 포함되지 않습니다.

## PC 없이 배포하기 (휴대폰 Chrome에서)
1. 이 ZIP을 휴대폰에서 압축 해제합니다.
2. GitHub 계정으로 새 저장소를 만듭니다. GitHub 웹의 **Add file → Upload files**에서 `Dockerfile`, `render.yaml`, `requirements.txt`, `server.py`, `.dockerignore`, `web/index.html`을 **원래 폴더 구조대로** 업로드합니다. 폴더 업로드가 어렵다면 GitHub 모바일 브라우저의 데스크톱 사이트를 이용하거나 `web/index.html`을 새 파일로 만듭니다.
3. Render.com 계정으로 로그인하고 **New → Blueprint**에서 저장소를 연결합니다. `render.yaml`의 무료 플랜이 현재 제공되는지 확인하고, 제공되지 않으면 Render에서 지원하는 플랜을 직접 선택해야 합니다. 클라우드 서비스에는 요금·사용량 제한이 있을 수 있습니다.
4. 배포가 완료되면 Render에서 발급한 `https://...onrender.com` 주소를 **휴대폰 Chrome**으로 엽니다. 상단 **AI 서버 상태**가 초록색이면 분석 준비 완료입니다.
5. 오디오 파일을 선택하거나 마이크 권한을 허용하고 녹음 → **실제 오디오 분석** → **분석 결과로 비트 생성** → **재생**.

**중요:** 이 ZIP만 다운로드해서 열면 클라우드 서버가 자동 생성되지는 않습니다. 서버 배포는 사용자의 GitHub/Render 계정에서 직접 진행해야 합니다. 이 대화에서 서버가 실제 배포된 것은 아닙니다. 배포 후에는 PC 없이 모바일에서 이용할 수 있습니다.

## 로컬 개발 (선택)
`pip install -r requirements.txt` 후 `python server.py`, 접속 `http://localhost:5000`.

## 개인정보 및 권리
허가된 오디오만 업로드하세요. 파일은 분석 후 삭제되지만 클라우드 서비스 운영자와 호스팅 정책에 따라 네트워크 및 서버 메타데이터가 처리될 수 있습니다. 마이크는 HTTPS 환경에서만 사용할 수 있습니다. 같은 스마트폰의 다른 앱에서 재생되는 음악은 마이크로 직접 캡처되지 않을 수 있습니다.
